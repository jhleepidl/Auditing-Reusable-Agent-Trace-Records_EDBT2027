# R23 CPU-only local development study

This protocol is written after reviewing R22 failures but before executing the new
capability controls or combined frontend on the retained candidates. All R22 task
templates, worlds, responses, cases and aggregate outcomes are already exposed.
This is not prospective model confirmation, not new native collection, and not an
increase in the count of independent benchmark tasks. No provider calls are made.

A. Expert-authored capability controls
- Author one executable source-DAG per each of the eight exposed templates.
- The author reads only public request, source layout, scope, schema and the existing
  public facts when writing the programs. No reference implementation or resolved
  gold operand may be imported into the program builder or compiler.
- Programs use the ORIGINAL r22.2 frontend and SHA-bound r22.1 DAG runtime, original
  64-node/depth16 limits, and existing public facts; template-specific structural
  selectors and public request text anchors are declared. No world-specific answer
  scalars or entity names may be inserted. Programs are NOT model outputs.
- Freeze eight annotations before scoring against the independent references.
- Execute unchanged annotations on all six retained source worlds (48 task/world
  compilations) and all 384 retained native-observation fixtures. Report development
  misses too. Reference comparison runs only after compilation/predictions exist.
- Banking controls obtain the source's 'self' token from the sender of the unique
  earliest historical transaction. This is an explicit convention of these retained
  public snapshots, not a general identity-inference algorithm. Missing/ambiguous
  structural selectors must abstain. Request anchors are template-specific.

B. Frontend repair, factorial retained-candidate cross-execution
- Preserve the original scalar annotation schema, all operations, budgets, operands,
  claims, observations, references, candidate selection, and ordinary interpreter.
- Topology: stable Kahn ordering of a complete acyclic DAG; never add/drop nodes,
  invent missing references, break cycles, or mutate operators/arguments/constants.
- Addressing: scope root becomes an explicitly bound read-only public-input view:
  retain all original scope fields, and expose common_scope, public_scaffold,
  endpoints and contract_template as exact copies of metadata already supplied to
  both arms. Reject field-name collisions. No fuzzy paths, inference from labels,
  lookup by task ID, or fallback to private source/reference/observations.
- Cross old / topology-only / addressing-only / combined for all eligible r22.2
  retained candidates, including development, primary, B1/B2/C and frozen-program
  transfer. Legacy r22.1 developmental annotations remain separate, not reinterpreted.
- Report compile status transitions, semantic status transitions, task-macro false
  pass and valid retention, errors and unknown promotions for all arms. Ordinary
  'verified' claim agreement is a secondary control, not the primary measure.
- Bootstrap pairs by original task-template unit; no case-level independence claims.
- Do not choose an output policy by its observed retention. All four factorial arms
  are reported. No new model-success claim or held-out generalization follows.

C. Verification and manuscript
- Keep upstream archive bytes untouched; bind all new code, inputs and results.
- Test preservation for previously valid topological programs and canonical paths,
  missing/duplicate/cyclic references, unsupported and wrong types, missing source,
  scope view immutability, and strict source address boundaries.
- Use current local CPU; record exact environment. Failure to obtain pinned native
  dependencies is a bounded reproducibility limitation, not a reason to defer the
  pure compiler/reference work. Never claim new native execution without receipt.
- Integrate supported CPU findings in the manuscript as retrospective development
  evidence. Preserve previous primary and negative model results. Do not substitute
  expert-authored programs for model accuracy. No new broad data-model framing.
