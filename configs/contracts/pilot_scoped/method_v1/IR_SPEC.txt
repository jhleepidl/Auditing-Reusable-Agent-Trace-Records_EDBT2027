# R21 common typed contract and bounded execution policy

This common IR is used by every construction arm. The executor imports no source reference, expected-value table, task utility, native solution, or model judge. Public scope metadata declares obligation IDs and shapes; candidate operands remain candidate data. A source quote/pointer check is structural support validation, not semantic certification.

`output_schema.json` is generated from `contract_executor.SCHEMA`. All keys in each typed object are required, unused state/query payloads are null, and extra keys are forbidden. Top-level keys: `ir_version` (`r21.1`), `scope_id`, `classification` (`state`, `query`, `unknown`), `clauses`, `unknown_reason`. A clause binds one public obligation ID to either a state entity conjunction or one query assertion. No authority hashes are inserted into this object: the calling protocol binds the immutable scope/packet hashes externally.

## APIs and scope policy

`validate(contract)` checks schema, pointer syntax, finite/type-correct operands, consistent kind, and declared identity/newness profiles. Invalid construction is ERROR, separately preserved.

`preflight(contract, public_task, packet=None, policy='scope')` validates exact scope ID/kind/path or declared one-segment path pattern; required property/operator/types; declared selector and identity policy; newness; dynamic-path/check operand bindings; and query role/property/unit/time/polarity. Public `eq` normalizes to IR `equals`, and `affirmative` to `positive`. Missing properties or obligations are incomplete coverage; extra clauses, selectors, properties, duplicate required checks, or changed operators are scope mismatches. Operands are never replaced with reference values. Task-subject query labels/aliases are public protocol labels; source-derived entity names remain candidate data.

`scope_source` adds the same literal request-quote and initial/schema JSON-pointer checks for all arms. Packet keys are `request` or `task_request`, `initial_state`, and `state_schema`. Schema evidence supports exact pointers into schema objects or concrete data pointers resolved through bounded local `$ref`/`$defs`; external refs and unresolved/cyclic expansions are refused. A wrapped `suites` schema may be projected by the public task suite. Initial pointers resolve against the immutable initial state. Neither policy proves semantic necessity.

`evaluate(contract, pre, post, output, *, public_task=None, packet=None, policy='scope')` returns verdict, admission record and per-obligation diagnostics. Unavailable required observations (`None`) are UNKNOWN, distinct from a fully observed empty collection/value/output. A supported actual failure dominates unknowns in other obligations. Missing unsupported clauses are not silently filled. Additional obligations are recorded and do not become extra conditions in the reference scope. A full PASS requires supported complete declared coverage.

## State semantics

All checks in one clause apply to the same selected entity. Operators: `equals`, string `contains`, array `member`/`not_member`, numeric `gt/ge/lt/le`, ISO `date`/`month_day`, `exists`, `absent`, and `changed`. Arrays and booleans have actual typed equality; true is not numeric one. `$value` denotes the target entity itself. Concrete paths use JSON pointers; relative properties/selectors may use nested slash paths. Invalid selectors remain errors, not repaired defaults.

Identity profiles: `stable_id` (declared scalar ID, duplicate/missing IDs UNKNOWN), `dict_key`, `message_multiset` (declared fingerprint fields), `scalar_set`, `singleton`, and generic legacy positional `position`. Newness: `pre_id_absence`, `pre_key_absence`, `count_increase`, `none`, or positional `index_absence`. Stable-ID novelty is invariant to list order and does not infer new identity after deleting/recreating the same ID. Message novelty is a fingerprint count increase. Positional novelty is a separate declared policy, never substituted for stable ID. Public membership/path bindings connect the username/destination captured from a path to the corresponding operand without knowing its correct value.

## Query grammar (fixed before model development)

Recognized records bind an entity to field/value assertions, e.g. `Speedy Rentals — rating 4.5, total 336`; `Entity has rating 4.5`; or `[binding_role] Entity — total 336 for 3 days`. Fields may use `:`, `=`, `is`, `of`, or `equals`. Fixed aliases: amount/ spending/ paid; rating/ rated/ score; total/ total cost/ cost/ price; flight_number/ flight number/ flight/ number. Aliases apply only in recognized field syntax; arbitrary numeric co-occurrence is insufficient. Flight identifier fields may establish their own entity anchor. Public task-subject aliases are normalized only from the published inventory. Field values remain bound to entity, property and role.

Affirmative selection forms `I recommend Entity`, `I select Entity`, and named selected-company forms are recognized; bare names are bounded entity records. `Not: Entity — field value`, `Entity is not rated value`, and `field is not value` are negative. A correct assertion cannot erase an explicit conflicting assertion for the same bound fact. Double-quoted whole records and `>` lines are mentions, not assertions. Complete quotation-only records do not satisfy an affirmative obligation. `Entity — ` and `Entity is an option` are complete bounded records that omit requested facts. Unrelated recognized records or quoted context do not suppress an established scoped fact. Unrecognized/incomplete target prose remains UNKNOWN; unsupported fragments are not deemed complete records. Empty observed answers FAIL; unavailable answers are UNKNOWN. Complete recognized records with a required property/role/entity omitted FAIL.

Suffix qualifiers are `USD`, `EUR`, `GBP`, dollars/euros/$/€/£, or points, optionally followed by `for/over N days`; temporal-only `for/over N days/people/persons/passengers` is supported. Seven days normalizes to `seven_day_rental`, three days to `three_day_rental_per_car`, four days to `four_day_rental`, two people to `two_person_flight`. Missing qualifiers use the immutable request's declared role/time. Public `money_amount`/`money_total` are monetary dimensions: recognized currencies establish that dimension but do not certify source currency, which is explicitly outside this scope. Currency on a rating conflicts with `rating_points`. Generic IR explicitly declaring literal USD/GBP still rejects a different currency. Unknown syntax is not guessed.

These rules are a finite executable assertion relation, not a natural-language semantic oracle. Development compiler comparison is an exposed implementation diagnostic, not a construction arm or confirmation result. Legacy scalar-only query facts are not upgraded into bound assertions. R20 primary metrics and candidate bytes are unchanged; no lossless old-to-new query re-evaluation is claimed.
